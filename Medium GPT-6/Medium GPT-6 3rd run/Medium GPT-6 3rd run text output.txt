Digital Forensic Examination Report
Evidence reviewed: Seven ZIP archives containing Windows filesystem artifacts, registry data, application data, event logs, Prefetch records, and forensic reports.

Principal period identified: 20–21 October 2026 UTC, with some associated artifacts dated 22 October in local time.

Assessment approach: Evidence-led, without a presumption of compromise.

2. Executive assessment
The accessible evidence documents a Windows environment containing ordinary application installation activity, an email advertising a free holiday, a downloaded batch script capable of disabling Task Manager, and execution-related artifacts associated with that script.
High confidence — Script functionality

A recovered free-holidays.bat file contains a Windows registry command that, if successfully executed in the relevant user context, sets DisableTaskMgr to 1.



High confidence — Download

Edge History records a completed download of the batch file from https://chrysanthou.cy/free-holidays/ on 21 October 2026 at 22:09:42 UTC.



Moderate-to-high confidence — Execution association

Prefetch records show cmd.exe execution around 22:10:44 UTC and explicitly reference FREE-HOLIDAYS.BAT. This strongly supports the script being involved in command-shell activity, but does not independently prove the registry operation succeeded.



Unresolved — Actual system impact

The examination did not establish that Task Manager was successfully disabled, that any setting persisted, or that an unauthorized person controlled the system.



A separate issue materially affects the evidential foundation: the supplied Autopsy workbook reports a SHA-256 verification failure for the source VHD. This requires reconciliation before treating the exports as a verified representation of the original evidence.

Overall assessment: The artifacts are consistent with exposure to a potentially deceptive email and execution-related activity involving its associated downloadable script. However, they do not establish a completed compromise, malicious intent, attribution, or actual modification of the Task Manager restriction.

Finding 3 — The downloaded batch file contains a Task Manager restriction command
Direct observation

The recovered file is 131 bytes. Its contents are:
@echo off
reg add "HKCU\Software\Microsoft\Windows\CurrentVersion\Policies\System" /v DisableTaskMgr /t REG_DWORD /d 1 /f
exit /b


Precise source

16831-Downloads.zip → 16831-Downloads/16835-free-holidays.bat.

Interpretation

The script is designed to write the value:

HKCU\Software\Microsoft\Windows\CurrentVersion\Policies\System\DisableTaskMgr

with type REG_DWORD and data 1.

A successful write would configure a restriction on Task Manager for the relevant user context.

The file contains no additional commands for credential collection, network communication, persistence, or data exfiltration.

What is not established: The script text does not establish successful execution, a changed registry value, or an enduring restriction.

Confidence: High for functionality, because the command is directly readable.

Administrative restriction, training, and testing are possible explanations. However, the mismatch between the holiday-themed filename and its actual function makes the file worthy of further scrutiny.

5. Correlations, contradictions, and alternative explanations
Correlations
Email destination and downloaded file

The email and browser download independently contain the same URL. This supports a common destination and an association between the message and the file. It does not prove the message was clicked.

Batch-file access and command-shell execution

The reported batch-file access and cmd.exe execution coincide at 22:10:44 UTC. More importantly, the Prefetch referenced-file records explicitly include FREE-HOLIDAYS.BAT.

Together, these observations provide a stronger execution association than proximity alone.

Thunderbird installation and mailbox presence

A Thunderbird installation, Thunderbird execution records, and a Thunderbird profile containing the email are consistent with mail-client use. The precise way the email was acquired remains unresolved.
Contradictions and unresolved issues
Issue	Evidential consequence
The email is dated before the recorded Thunderbird installation	The message may have existed on a mail server before local setup; it does not establish the time of local receipt or reading
The batch file targets a precise HKCU policy key, but the reviewed RegRipper check uses a different path	A negative result from that check cannot exclude the targeted registry value
Task Manager has Prefetch runs after the suspected script activity	These do not establish whether its interface was usable or blocked
The source VHD failed hash verification	Provenance and integrity need independent reconciliation
The script's filename suggests a holiday offer, but its code modifies Task Manager policy	Supports a deceptive-function concern, not an attribution or intent conclusion

Alternative explanations
Three broad hypotheses remain compatible with portions of the evidence.

1. Controlled demonstration or experiment. The environment may have been used to demonstrate email-based delivery, batch execution, and Task Manager restrictions. The named forensic image, concentrated activity, and small script could be consistent with such a scenario, but none independently proves it.

2. Deceptive delivery and execution. A recipient may have encountered an unsolicited holiday message, obtained the offered file, and run it without understanding its functionality. The URL, script contents, and execution artifacts support investigating this hypothesis. Human deception and unauthorized activity are not independently demonstrated.

3. Authorized administrative activity. The script could have been deliberately obtained and executed to test or apply a restriction. The actual command is compatible with that purpose, although its holiday-themed presentation would require explanation.

The currently examined artifacts do not reliably distinguish these hypotheses.

An additional caution concerns Excel.xlsx, worksheet Interesting Items, rows 2–18. Those rows identify remote-management-related programs or files, including standard Windows RDP and Quick Assist components. They are detection or categorization results, not evidence of an established remote session.

6. Limitations and questions the evidence cannot answer
The most consequential limitation is that the complete source image is unavailable and its supplied report identifies a hash-verification failure.

Other important constraints are:
- Registry state: The exact DisableTaskMgr value was not independently recovered and interpreted from the relevant user hive.
- Event logs: The .evtx files were present but not decoded in this examination. Process creation, policy changes, security events, and application errors therefore remain unassessed.
- Prefetch: The supplied extracted database was examined, but individual raw .pf files were not independently validated. Prefetch does not ordinarily establish complete command lines or success of individual commands.
- Email provenance: The mailbox copy was examined, but server-side delivery, authentication, and access logs were not available. Sender identity and human interaction are unverified.
- Application data: Selected Edge and Thunderbird records were examined, not all browser storage, account databases, caches, deleted records, or application logs.
- Filesystem completeness: The supplied files are selections from a larger filesystem. Missing artifacts cannot be assumed absent from the original system.
- Attribution: A Windows profile or account label cannot identify the person operating the system at a given moment.
- Intent: No reliable conclusion can be made about whether the activity was authorized, accidental, experimental, or malicious.
The evidence does not currently establish credential theft, exfiltration, persistence, remote control, successful Task Manager restriction, or complete system compromise. These are unresolved questions, not conclusively negative findings.

Obtain the original VHD and acquisition records. Independently recompute its SHA-256, compare with acquisition documentation, and establish whether the exports correspond to the verified image.

Priority: Critical — affects reliance on all derived records.

Examine NTUSER.zip/NTUSER.DAT, including recoverable transaction data, at Software\Microsoft\Windows\CurrentVersion\Policies\System. Determine whether DisableTaskMgr exists, its actual type and value, and whether any recoverable history supports modification.

Priority: Critical — resolves the principal unverified system-effect question.



3

Parse relevant Windows event logs

Examine Security, System, Windows Defender, PowerShell, and application-related logs around 21 October 2026, 22:08–22:48 UTC. Look for process creation with command-line data, access or policy errors, detection results, and authentication/session context.

Priority: High — potentially corroborates execution and its consequences.



4

Validate Prefetch independently

Decode the original CMD.EXE, TASKMGR.EXE, and Thunderbird Prefetch files. Compare embedded run counts, execution timestamps, referenced files, and tool output for consistency.

Priority: High — verifies the strongest execution association.



5

Reconstruct the download and local interaction sequence

Correlate browser download records, original filesystem timestamps, shell artifacts, UserAssist, and any available NTFS journal records. Determine whether the script was explicitly opened, renamed, or invoked through another process.

Priority: High — helps distinguish download, access, and execution.



6

Expand mailbox and provenance analysis

Examine the complete original message, Thunderbird message state, account configuration, and any available mail-server logs. Establish whether the message was delivered, synchronized, opened, or accessed through a link interaction.

Priority: Medium — clarifies the email's role without assuming user behavior.



7

Assess the wider environment

Review additional application, service, scheduled-task, persistence, and network artifacts only after establishing reliable provenance and the principal sequence of events.

Priority: Medium — identifies corroboration or unrelated activity while avoiding scope-driven assumptions.




Final conclusion
The strongest supported sequence is that a holiday-themed message existed in a Thunderbird mailbox, a batch file was subsequently downloaded from the same URL advertised in the message, and forensic execution artifacts associated that file with cmd.exe. The batch file contained a command to disable Task Manager for the current Windows user.

The evidence is strong for file content, download, and an execution association, but insufficient to establish that the registry change succeeded or that the activity constituted an unauthorized compromise.

The reported source-image SHA-256 verification failure is a material concern that should be resolved before final evidential reliance.

This assessment is therefore best treated as an interim forensic finding based on accessible extracted artifacts, not a final determination of compromise, attribution, or intent.
